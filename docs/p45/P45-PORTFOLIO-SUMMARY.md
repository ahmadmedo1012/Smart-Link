**النطاق:** W1 من P45 لكل مستودع (الأربعة) — البداية من مراسي P44 والانتهاء بالرؤوس الخضراء أدناه. **21 التزامًا** عبر الأربعة، CI أخضر عند الرأس النهائي لكل مستودع. سجلات التنفيذ الكاملة بالأدلة: docs/p45/ داخل كل مستودع (وتُحدَّث مع كل موجة).

## أ. الملخص التنفيذي

موجة W1 حوّلت نتائج التدقيق الأربعة (أُنجزت بوكالة قراءة فقط، بأدلة file:line) إلى **ست مبادرات رأسية جوهرية** (≥2 لكل منتج — المعيار تحقق) + حراس CI جدد + توثيق خط أساس لكل مستودع:
1. **SmartBot:** طبقة التسليم اليدوي P43-SB2 (API كاملة بلا مستهلك) نالت واجهتها الأولى (إيقاف بوت/مسؤول/دورة حياة/ملاحظات + طابور المشغل) — وربط eslint الواجهة بـ CI (فجوة P44) + عمق مراقبة التنفيذات (فلاتر/ترقيم/مشترك/رابط وارد) + قوالب وتكرار.
2. **Smart-Order:** عيبان حقيقيان مُصلحان: **إلغاء الطلب كان يحرق المخزون نهائيًا** (استرجاع بحارس مرة-واحدة في التوأمين) و**المرتجعات المستحقة كانت تختفي من التسوية** (قسم «استرجاعات مستحقة» + CSV من البنّاء نفسه) + إيصال موحد قبل الإرسال + زمن-في-حالة.
3. **Smart-Menu:** **انتهاك قاعدة r93-N5** في الإحصاءات المتقدمة أُصلح (الملغى كان ينفّخ الإيراد/AOV/الساعي/الحصص) + حدود يوم طرابلس + اكتمال إدارة الفئات (ترتيب/تكرار لأول مرة) + تسميات اللغتين الصادقة + idempotencyKey للويب + تغطية اختبارية لثغرة موثقة (بتصحيح صادق: r119-B6 كانت مصلحة أصلًا والفجوة اختبارية).
4. **Smart-Link:** **حرس ميزانية الحزمة** (first لكل مسار — three.js بلا بوابة منذ البداية) + **محدد «أي عالم يناسب عملك؟»** + **مصفوفة مقارنة صادقة** + **صفحات هبوط المنتجات /menu /bot /order** (6→9 مسارات قابلة للفهرسة، JSON-LD مرابط، صفر مرآة).

## ج. النتائج النطاقية

- **حراس جدد عبر العائلة:** bundle budget (Smart-Link) · eslint-in-CI (SmartBot، فجوة P44) · اختبارات money-truth موسعة (Smart-Menu) · توأمان متطابقان مع عمود جديد (Smart-Order).

- **انضباط مشترك:** mobile/ صفر delta في الـ 21 التزامًا كلها (تُحقق بـ git diff لكل مستودع) · لا Vercel · لا مدفوع · لا دمج Dependabot.
