# مقارنة المشروعين الأساسيين — Smart Menu مقابل SmartBot

> **الغرض:** مقارنة استراتيجية وتقنية وقياسية بين المشروعين الأساسيين لمنظومة SmartLink، بناءً على كود المستودع (ahmadmedo1012/Smart-Link)، والقياسات الحية الموثّقة في `docs/lighthouse-baseline.md`، وبيانات Lighthouse لست جولات قياس (before / after / r2 / r2b / r2c / r2d).
> **التاريخ:** 2026-09-06 — بعد الجولة الثالثة من التحسين (r3).

## 1. بطاقة تعريف كل مشروع

| | **Smart Menu** | **SmartBot** |
|---|---|---|
| **النطاق** | menu.smart-link.ly | bot.smart-link.ly |
| **التعريف (من الموقع)** | المنيو الرقمي التفاعلي للمطاعم مع طلبات واتساب | البوت الذكي لأتمتة الردود على صفحات فيسبوك |
| **المشكلة التي يحلها** | قوائم الورق الثابتة: تكلفة طباعة متكررة، لا تحديث فوري، لا تحليلات للطلبات | غرق صفحات الأعمال برسائل العملاء وإبطاء الرد = خسارة مبيعات وسمعة |
| **الجمهور المستهدف** | المطاعم والمقاهي وكل نشاط له قائمة طعام/خدمات | أصحاب صفحات فيسبوك التجارية والوكالات التي تدير صفحات متعددة |
| **قناة التحويل** | زبون يمسح QR → يطلب عبر واتساب مباشرة | رسالة صفحة → رد آلي فوري بتصنيف النية |
| **نموذج الإيراد الحالي** | خطة أساسية مجانية + مدفوعة قادمة | خطة أساسية مجانية + مدفوعة قادمة |
| **التوكن البصري** | `--gradient-smart-menu`: `oklch(0.7 0.19 60 / …)` — برتقالي ذهبي فاتح | `--gradient-smart-bot`: `oklch(0.55 0.15 280 / …)` — بنفسجي هادئ |

## 2. المقارنة الاستراتيجية

### 2.1 حلقة القيمة لكل مشروع

**Smart Menu** يبني حلقة قيمة **فورية ومحسوسة**: الزبون يمسح الرمز بلحظة الجلوس، يتصفح صور الأطباق، ويرسل طلبه على واتساب خلال دقيقة. القيمة تظهر في نفس الجلسة، ودورة الإقناع قصيرة جداً (المطعم يجرّب ثم يتبنى). لهذا يُقدَّم أولاً في صفحة الأسعار وفي التنقل الرئيسي — وهو «رأس حربة» البيع للمنصة ككل.

**SmartBot** يبني حلقة قيمة **تراكمية**: قيمته تظهر عبر الزمن — كل رسالة يرد عليها تلقائياً هي دقيقة محفوظة من وقت الموظف، وكل تصنيف نية هو بيانات تُحوَّل لاحقاً إلى تقارير. دورة الإقناع أطول (يحتاج صاحب الصفحة أن يرى تراكم الردود)، لكن الالتصاق (retention) أعلى لأن البوت يصبح جزءاً من عملية التشغيل اليومية.

### 2.2 التسعير داخل الصفحة

كلاهما يُعرض بخطة أساسية **مجانية** تماماً (نقطة دخول موحّدة بلا احتكاك)، مع «قريباً — خطط مدفوعة» مشتركة. الفوارق في قوائم الميزات المعروضة:

| الميزة المعروضة | Smart Menu | SmartBot |
|---|:---:|:---:|
| الواجهة/اللوحة | لوحة تحكم عربية | لوحة تحكم متكاملة |
| القناة | طلبات عبر واتساب | ردود تلقائية ذكية |
| التخصيص | رمز QR مخصص | إدارة صفحة واحدة |
| الولاء/الانتشار | برنامج ولاء وإحالات | بث جماعي |
| البيانات | إحصائيات أساسية | تقارير أساسية + تصنيف النوايا |

نقطة لافتة: Smart Menu يعرض **6 ميزات** في بطاقة الأسعار و**6 ميزات** في بطاقة الخدمات، ومثلها SmartBot — توازن عرض مقصود لا يُرجّح منتجاً على آخر في صفحة تجمعهما تحت مظلة واحدة.

### 2.3 المخاطرة والنضج

- **Smart Menu** أقل تعقيداً تقنياً (قوائم + واتساب + QR) → أسرع في الصيانة والتوسع، وأقل عرضة لأعطال الطرف الثالث.
- **SmartBot** يعتمد على واجهات فيسبوك (Meta) البرمجية → مخاطرة منصة أعلى (تغييرات السياسات/الأسعار من Meta)، لكنه أعلى جداراً تنافسياً حين يعمل باستقرار.

## 3. المقارنة التقنية داخل منظومة smart-link.ly

### 3.1 الحضور المتساوي (هندسة العرض)

| نقطة الحضور | Smart Menu | SmartBot |
|---|:---:|:---:|
| روابط حية في الكود (`src/`) | **7** | **7** |
| JSON-LD `subOrganization` | ✓ (مع وصف) | ✓ (مع وصف) |
| JSON-LD `sameAs` | ✓ | ✓ |
| بطاقة في قسم الخدمات (services) | ✓ أول بطاقة | ✓ ثاني بطاقة |
| قسم العرض التفاعلي (product-showcase) | ✓ هاتف بتمرير حقيقي | ✓ متصفح مع parallax |
| التنقل الرئيسي + قائمة المنتجات | ✓ | ✓ |
| بطاقة في صفحة الأسعار | ✓ | ✓ |
| الفوتر | ✓ | ✓ |
| CTA الرئيسي | ✓ | — (CTA يركز على Smart Menu كبوابة) |

الخلاصة الهندسية: توازن صارم — 7 نقاط حضور لكل منتج، بلا ترجيح في البنية، والترجيح الوحيد مقصود تسويقياً في زر CTA الرئيسي (بوابة الدخول الأسرع إقناعاً).

### 3.2 الهوية البصرية الموحّدة (نتيجة الفريق 1 + جولات التدقيق)

كلا المشروعين يستمد هويته من نفس النظام اللوني للأم العلامة `SmartLink`:
- اللون الأساسي الموحّد: `oklch(0.55 0.19 45)` — **بايت-بايت مطابق** لما يُصيَّر حياً على موقعَي Smart-Menu وSmartBot (تحقق الجولة 1: `lab(46.3257% 53.1936 85.8773)`).
- التمييز البصري بين المنتجين يأتي من **توكنات التدرج** فقط (برتقالي ذهبي مقابل بنفسجي)، لا من ألوان خارج النظام — بوابة grep: **صفر ألوان Tailwind خام** في كل `src/`.
- خط العناوين Readex Pro والسلسلة `--font-heading` — نفس سلسلة SmartBot الحية حرفياً.

### 3.3 الأصول الرقمية في المستودع

| الأصل | Smart Menu | SmartBot |
|---|---|---|
| لقطة عرض حقيقية | `public/images/smart-menu.jpg` (قائمة طويلة تُمرَّر داخل الهاتف) | `public/images/smart-bot.jpg` (واجهة داخل إطار متصفح) |
| دورها | عنصر LCP سابق — صُغّر عبر next/image بعد الجولة 2 | نفس المعالجة |

## 4. المقارنة القياسية (أثر المشروعين على أداء الموقع المظلّ)

الموقع `smart-link.ly` هو واجهة المشروعين معاً، لذا فإن قياساته تعكس جودة تقديمهما:

| الصفحة | علاقتها بالمنتجين | قبل (سبتمبر r0) | بعد الجولة 2 (r2d-live) | الدلتا |
|---|---|:---:|:---:|:---:|
| `/` (الرئيسية) | تعرض المشروعين معاً | 82 | **93** | +11 |
| `/about` | قصة المنظومة والقيم | 64 | **85** | +21 |
| `/pricing` | بطاقتا المشروعين | 65 | **92** | +27 |
| `/contact` | بوابة طلب الخدمتين | 65 | **98** | +33 |
| `/privacy` | سياسة المشروعين | 66 | **96** | +30 |
| `/terms` | شروط المشروعين | 66 | **89** | +23 |

**LCP الرئيسية: 4.1s → 2.9s** (و2.14s في متصفح حقيقي مخنوق) — وهذا مباشرة أثر على أول انطباع لزائر قادم يقيّم المشروعين.

ملاحظة منهجية: قياسات الحاوية المشتركة تتذبذب (نفس الكود سجّل 74–93 على الرئيسية عبر الجولات)؛ الأرقام أعلاه من القياسات الفردية المستقرة الموثّقة، وقياس PageSpeed Insights الرسمي عادة أعلى.

## 4-bis. المواجهة الحية المباشرة — قياسات من مواقع المنتجات نفسها (ج4، 2026-09-06)

> قياس مباشر بالأدوات نفسها (curl + Lighthouse mobile من نفس الحاوية والوقت) للمواقع الثلاثة — أول قياس تفاحي حقيقي بين المشروعين والمظلة.

### 4-bis.1 التسليم والأداء الخام

| المقياس | المظلة smart-link.ly | **Smart Menu** | **SmartBot** |
|---|:---:|:---:|:---:|
| TTFB | **56ms** (ثابت مُسبق التصيير) | 344ms (SSR ديناميكي) | 359ms (SSR ديناميكي) |
| حجم HTML | 153KB | 121KB | 115KB |
| استراتيجية التخزين | max-age=0, must-revalidate | 60s + SWR يوم | no-store (ديناميكي كامل) |
| الخادم | Vercel | Vercel | Vercel |

الفرق البنيوي واضح: المظلة **صفحات ثابتة مُسبقة التصيير** (TTFB 56ms) بينما المنتجان **تطبيقات SSR ديناميكية** (لوحات تحكم وحالات جلسات) — هذا ليس عيباً بل طبيعة كل نوع: صفحة تعريفية مقابل تطبيق تفاعلي.

### 4-bis.2 Lighthouse mobile (نفس الحاوية، نفس اللحظة)

| المقياس | المظلة (بعد ج4) | **Smart Menu** | **SmartBot** |
|---|:---:|:---:|:---:|
| **الأداء** | 88 | **67** | **93** |
| الإتاحة | **100** | 100 | 96 |
| أفضل الممارسات | 100 | 100 | 100 |
| SEO | 100 | 100 | 100 |
| LCP | 3.1s | 4.5s | **2.2s** |
| FCP | 1.4s | **1.2s** | 1.7s |
| TBT | 280ms | 710ms | 250ms |
| CLS | **0** | **0** | 0.013 |

**قراءة النتائج:**
- **SmartBot هو الأسرع** بين الثلاثة (LCP 2.2s، TBT 250ms) — لوحة SSR خفيفة وبجاهزية عالية.
- **Smart Menu يعاني** (67) — LCP 4.5s وTBT 710ms هما أعلى أرقام في المنظومة؛ صفحته الرئيسية أثقل (صور أطباق + منطوق عميل كامل). **هذا أكبر فرصة تحسين معروفة في المنظومة حالياً** — تطبيق نفس منهجية الجولات 2-4 (نزع framer من المسار الحرج + CSS scroll-driven) عليه سيرفعه على الأرجح إلى 85+.
- **المظلة تحقق الإتاحة الكاملة (100) التي ينقصها SmartBot (96)** وتتفوق على Smart Menu في كل شيء — بعد أن كانت قبل أربع جولات (68 متوسطاً) أدنى من الاثنين.
- الإتاحة الفريدة: **المنظومة الثلاثة كلها a11y/bp/seo ممتازة** (96-100 شامل).

### 4-bis.3 تكافؤ الهوية عبر المواقع الثلاثة (تحقق بايت-بايت)

CSS المُصدَر حياً من كل موقع — **التوكنات الثلاثة متطابقة حرفياً في المواقع الثلاثة**:

| التوكن | المظلة | Smart Menu | SmartBot |
|---|:---:|:---:|:---:|
| `--primary` (داكن) | `lab(46.3257% 53.1936 85.8773)` | نفسه | نفسه |
| fallback hex | `#bc4700` | `#bc4700` | `#bc4700` |
| `--primary` (فاتح) | `#792c00` | `#792c00` | `#792c00` |
| خطوط العناوين | Readex Pro (next/font) | Readex Pro (مستضاف ذاتياً `/fonts/`) | Readex Pro (مستضاف ذاتياً `/fonts/`) |
| خط الجسم | Cairo | Cairo | Cairo |
| اللغة/الاتجاه | ar/rtl | ar/rtl | ar/rtl |

جميع CSS: المظلة 75KB | Smart Menu 284KB | SmartBot 175KB — المنتجات تحمل أنظمة تصميم أكبر (لوحات تحكم متعددة الصفحات).

### 4-bis.4 الأثر الصافي للجولات على موقع المظلة (خادم المنتجين)

المظلة التي «تبيع» المشروعين قاست عبر الجولات: 82 → 88 (الرئيسية)، والمتوسط 68 → 90.5 — **أي أن واجهة عرض المشروعين أصبحت الآن في مستوى SmartBot تقريباً (88 vs 93) وبإتاحة كاملة (100 vs 96)**، رغم أنها الأغلى محتوى (153KB HTML بصور ومعارض).

## 5. الخلاصة التكاملية — لماذا هما مشروعان لا مشروع واحد

1. **تناوب أدوار:** Smart Menu هو «الصفقة السهلة» (تجربة قابلة للعرض في 30 ثانية أمام صاحب مطعم)، وSmartBot هو «العقد المتكرر» (اشتراك تشغيلي يومي). الأول يجلب العملاء بسرعة، والثاني يبقيهم.
2. **تغطية قطاعين مختلفين:** مطاعم/تجزئة مقابل خدمات/وكالات — المنظومة لا تعتمد على دورة اقتصادية لقطاع واحد.
3. **مشترك تقني بلا ازدواج:** كلاهما يعمل بلا قاعدة بيانات مشتركة أو خدمات خلفية مرتبطة — استقلالية كاملة تسمح بتعطيل أحدهما دون لمس الآخر.
4. **خطر التوحيد الخاطئ:** لو دُمجا في منتج واحد لخسرا كليهما وضوح الرسالة؛ الفصل النظيف (نطاق مستقل + بطاقة + JSON-LD subOrganization) هو ما يجعل لكل منهما هوية قابلة للتصنيف في محركات البحث.

**التوصية:** الحفاظ على المظلة الموحدة (smart-link.ly) كبوابة، مع قياس تحويل منفصل لكل مشروع (أثر نقرات بطاقة كل منتج) عند توفر Analytics — وهذا مفعّل أصلاً عبر @vercel/analytics المنصّب في الجولة صفر.
